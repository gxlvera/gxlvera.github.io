Proxy Server Component 2: Tokenization (Token-in-Token-Out)

Why tokenization on the Proxy Server instead of the Rollout Engine (e.g., SGLang)?

TURN 01
SYSTEM USER Rollout Engine ASSISTANT · A1
TURN 02
SYSTEM USER ASSISTANT · A1 TOOL RESPONSE Rollout Engine A2
Decode - encode is not round-trip equal.
model generates token_id: 826 token_id: 4172 decode “he” + “llo” encode token_id: 15339“hello”
≠  cross-turn mismatch!
  • can’t merge
  • hurt KV cache hit rate
Inference engine can’t be stateful ❌

Multi-turn: Append-only delta tokenization

TURN 01
SYSTEM USER Rollout Engine ASSISTANT · A1
TURN 02
SYSTEM USER ASSISTANT · A1 preserve
Δ TOOL RESPONSE delta-tokenization
Rollout Engine A2

Advantages

  • Accuracy Re-tokenization across turns may change sampled token IDs.
  • Efficiency O(TN) vs O(N). Tokenization becomes a bottleneck when turn count is large and context is long.

Model specific adapter for multi-turn merging

REQUIRED INVARIANT append(history, new turn) = apply_chat_template(full history) exact token-ID equality
